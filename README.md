# 오목 도우미 (Omok Helper)

스마트폰 화면에 보이는 오목 바둑판을 **실시간으로 감지**해서, 다음에 둘 좋은 자리를 게임 화면 위에 표시해 주는 안드로이드 앱입니다.
정보 수행평가(모의 테스트)용으로 만든 프로젝트입니다.

## 설치 방법

1. 이 저장소의 **Releases → `latest`** 에서 `OmokHelper.apk` 를 휴대폰으로 다운로드합니다.
   (또는 **Actions** 탭 → 가장 최근 빌드 → `OmokHelper-apk` 다운로드 후 압축 해제)
2. 휴대폰에서 APK를 열어 설치합니다. "출처를 알 수 없는 앱" 설치 허용이 필요할 수 있습니다.

## 사용 방법

1. 앱에서 **판 크기(15/19)** 와 **규칙** 을 게임과 같게 고르고, **AI 생각 시간**(0.5/1.5/3초)을 정합니다.
2. **다른 앱 위에 표시** 권한을 허용합니다.
3. **화면 감지 시작** → 화면 녹화를 허용합니다.
4. 오목 게임을 열고, 떠 있는 패널의 **[판 맞추기]** 를 누릅니다.
5. 바둑판의 **맨 왼쪽 위 교차점**, **맨 오른쪽 아래 교차점** 을 차례로 맞추고 **[저장]** 합니다.
6. 이제 판이 바뀔 때마다 추천 자리에 고리가 나타납니다. (빨강 1순위 · 주황 2순위 · 파랑 3순위 이하)
   패널에는 좌표와 이유(예: `H8 4-3 공격 (필승)`), 필승 수순이 표시됩니다.

### 게임 중에 흑/백 바꾸기

패널 제목줄의 **`나: 자동 ⇄`** 칩을 누를 때마다 **자동 → 흑 → 백** 순서로 바뀝니다. ([설정]의 "내 돌"에서도 고를 수 있어요)

- **자동** : 지금 차례인 쪽의 추천을 보여 줍니다.
- **흑 / 백** : 내 차례일 때만 추천을 보여 주고, 상대 차례에는 "상대 차례 — 기다리는 중"으로 표시합니다.

### 패널의 [설정]

| 항목 | 설명 |
|---|---|
| 내 돌 | 자동 / 흑 / 백 |
| 판 프리셋 | `[저장 1~3]` : 지금 바둑판 위치와 크기(15/19줄)를 저장 · `[1~3]` : 저장한 위치를 바로 불러오기. 게임이나 화면 배치마다 저장해 두면 [판 맞추기]를 다시 할 필요가 없습니다 |
| 표시 크기 | 작게 / 보통 / 크게 — 추천 고리와 패널 글자 크기 |
| 인식 결과 보기 | 켜면 앱이 읽은 돌(흑 = 하늘색 점, 백 = 분홍 점)과 금수 자리(빨간 ×)를 교차점 모서리에 작게 표시. 인식이 맞는지 확인할 때 사용 |
| 흑 차례 색 / 백 차례 색 | 흑 차례 추천과 백 차례 추천의 고리 색을 따로 고름 (기본 · 네온 · 파스텔 · 고대비 · 흑백). 자동 모드에서 어느 쪽 추천인지 색으로 바로 구분되고, 패널 첫 줄에도 그 색 점(●)이 붙음 |
| 패널 색 | 다크 · 라이트 · 네이비 · 우드 · 반투명 (누를 때마다 다음 색) |

표시 크기를 바꿔도 추천 고리는 돌 인식에 쓰는 교차점 한가운데를 가리지 않도록 설계했고, 모든 색·크기 조합에서 고리가 돌로 잘못 인식되지 않는지 테스트로 확인합니다.

## 🔑 키 (라이선스)

키가 없어도 앱을 쓸 수 있지만, 아래 기능은 **키를 등록해야** 열립니다.

| 기능 | 키 없음 | 키 등록 |
|---|---|---|
| 내 돌 선택 | 자동만 | 자동 / 흑 / 백 |
| 추천 개수 | 1개, 3개 | 1개, 3개, **5개** |
| AI 생각 시간 | 0.5초, 1.5초 | 0.5초, 1.5초, **3초** |

**키의 규칙**
- **한 기기 전용** : 키는 발급받은 기기에서만 작동합니다. 다른 휴대폰에 넣으면 "이 기기용 키가 아닙니다"가 나옵니다.
- **한 달 만료** : 발급할 때 정한 날짜(기본 30일)까지만 쓸 수 있고, 지나면 위 기능이 다시 잠깁니다. 만료 5일 전부터 첫 화면에, 3일 전부터 게임 위 패널에 알림이 뜹니다.
- **갱신** : 같은 기기 코드로 새 키를 받아 첫 화면에서 [키 갱신]을 누르면 이어서 쓸 수 있습니다.
- 예전 방식 키(`OMOK1-`, 기기 제한·만료 없음)는 **2026-11-30까지만** 쓸 수 있습니다.

**받는 방법** : 앱 첫 화면 "🔑 키" 칸의 **기기 코드**(예: `K7Q2-9XMA`)를 [기기 코드 복사]로 복사해 보내면, 그 기기 전용 키(`OMOK2-`로 시작)를 받을 수 있습니다. 문의 : Discord `axkoth`

**원리**
- **전자서명** (`LicenseKey.java`) : 키를 만드는 사람은 **비밀 키**로 키 내용(키 번호, 만료일, 기기 코드)에 ECDSA P-256 서명을 합니다. 앱에는 **공개 키**만 있어서 서명이 맞는지 확인만 할 수 있고, 새 키를 만들 수는 없습니다. 내용을 한 글자라도 바꾸면 서명이 맞지 않아 거부됩니다. 서버 없이 인터넷 연결 없이 동작합니다.
- **기기 코드** : 기기 고유 번호(ANDROID_ID)를 SHA-256으로 해시해서 40비트만 쓰고, 사람이 보내기 쉽게 `XXXX-XXXX`(헷갈리는 I·O·0·1 제외)로 보여 줍니다. 키 안에 이 값이 서명과 함께 들어 있습니다.
- **시계 되돌리기 방지** (`License.java`) : 지금까지 본 가장 늦은 날짜를 저장해 두고, 기기 시계를 과거로 돌려도 그 날짜보다 뒤로 가지 않게 합니다.
- **고정 서명키** (`signing/omok.keystore`) : 모든 빌드를 같은 키로 서명해서 업데이트 설치가 가능하고 기기 코드가 바뀌지 않게 합니다. 업데이트용 키이며 비밀이 아닙니다.

**한계** : 서버 없이는 완벽하게 막을 수 없습니다. 앱 데이터를 지우고 시계를 되돌리면 시계 방지를 피할 수 있고, 실력 있는 사람이 APK를 분해해 검사 부분을 고치면 잠금을 풀 수 있습니다. 대신 키를 위조하거나, 받은 키를 다른 기기에서 쓰는 것은 막습니다. 라이선스에서 2차 수정도 금지하고 있습니다.

**키 발급 (저작권자 전용)** — `tools/KeyGen.java`
```bash
java KeyGen.java issue 12 K7Q2-9XMA              # 12번 키, 그 기기 전용, 오늘부터 30일
java KeyGen.java issue 12 K7Q2-9XMA +60          # 60일
java KeyGen.java issue 12 K7Q2-9XMA 2027-03-01   # 2027-03-01까지
```
비밀 키 파일 `omok-private.key`가 같은 폴더에 있어야 하며, 이 파일은 `.gitignore`로 저장소에 올라가지 않게 막혀 있습니다. 한 달마다 같은 기기 코드로 다시 발급하면 갱신됩니다.

## 동작 원리

```
화면 캡처 ──▶ 바둑판 인식 ──▶ 수 분석 ──▶ 오버레이 표시
(0.6초마다)   (색상 판별)     (패턴+탐색)   (추천 고리)
```

### 1. 화면 캡처 — `CaptureService.java`
안드로이드의 `MediaProjection` API로 화면을 0.6초마다 이미지로 받아 옵니다.
같은 판이 두 번 연속 읽혀야 확정해서, 돌이 놓이는 애니메이션 중간 화면은 무시합니다.

### 2. 바둑판 인식 — `BoardDetector.java`
- 사용자가 맞춘 두 모서리 좌표로 15×15(또는 19×19)개 교차점의 위치를 계산합니다.
- 각 교차점 주변 작은 원 안 픽셀들의 **밝기·채도 중앙값**을 구합니다. (중앙값을 쓰면 선이나 마지막 수 표시에 덜 흔들립니다)
- 돌로 인정하려면 교차점 한가운데뿐 아니라 **바깥 고리(반지름 0.34칸)** 도 같은 색이어야 합니다. 게임이 금수 자리·미리보기에 그리는 작은 점, ×, 반투명 돌은 돌로 읽지 않습니다.
- 칸 한가운데에서 잰 **바둑판 색**과 비교해서
  - 훨씬 어둡고 무채색이면 → 흑돌 (빨간 표시 등 색이 있으면 제외)
  - 밝고 무채색이면 → 백돌
  - 그 외 → 빈칸

### 3. 수 분석 — `OmokEngine.java`
| 단계 | 내용 |
|---|---|
| 패턴 분석 | 빈칸에 돌을 놓았다고 가정하고 4방향(가로·세로·두 대각선)의 모양을 판별: 5목, 열린4, 4, 열린3, 3, 열린2, 2 |
| 점수 계산 | **공격 점수**(내가 둘 때) + **수비 점수**(상대가 둘 때 × 0.8). 4-4, 4-3, 3-3 같은 복합 공격은 큰 점수 |
| VCF 탐색 | 4를 연속으로 두어 이기는 수순(Victory by Continuous Fours)을 깊이 우선 탐색. 있으면 최우선 추천 |
| 상대 VCF 차단 | 상대에게 필승 수순이 있으면 그 자리에 가산점 |
| 한 수 앞 보기 | 상위 후보에 대해 "내가 둔 뒤 상대의 최선 공격"을 계산해 위험한 수를 감점 |
| 금수 유도 | 4를 만들었을 때 상대가 막을 자리가 **상대의 금수**(3-3·4-4·장목)라 못 막는 수를 필승으로 계산. 공격(주로 백)에서는 노리고, 수비(주로 흑)에서는 미리 막음. 연속 4 수순·깊이 탐색에도 반영 |
| 규칙(금수) | 흑·백 각각 **6목 이상(장목) / 3-3 / 4-4 금지**를 따로 켜고 끔. [자유룰]·[렌주룰] 버튼으로 한 번에 설정. 금지된 자리는 추천하지 않고, 장목 금지면 6목 이상은 승리로 계산하지 않음 |

### 3-1. 오목 기술·공식 — `Openings.java`, `Guide.java`, `OmokEngine.java`

| 기술 | 앱에서 하는 일 |
|---|---|
| **26주형** (초반 정석) | 첫 세 수가 어떤 주형인지 알아내 패널에 표시 (`📖 주형: 화월(花月) D4 · 흑 필승 주형으로 알려짐`). 판을 돌리거나 뒤집어도 인식. 흑 3수 차례에는 흑 필승으로 알려진 주형(직접: 화월·우월 / 간접: 포월·운월) 자리를 추천 |
| **4-3 / 4-4 / 3-3** | 두 위협을 한 번에 만드는 공격으로 높은 점수. 한 줄 안의 4-4(`X_XXX_X`)도 구분 |
| **VCF** (연속 4) | 4만 계속 두어 이기는 수순 탐색 |
| **VCT** (연속 3·4) | 4와 열린 3을 섞어 이기는 수순 탐색. 수비 쪽의 모든 막는 자리와 반격 4까지 검토. 상대에게 4-3급 위협이 있으면 3으로는 공격하지 않음. 짧은 수순부터 찾고(반복 심화), 찾은 계획을 기억해 다음 수에도 이어서 둠 |
| **금수 유도** | 상대가 막을 자리가 금수인 4를 필승으로 계산 (공격·수비 모두) |
| **수비 원칙** | 5목 막기 → 상대 필승 수순(VCF·VCT) 차단 → 열린 3 막기 → 4-3·3-3 자리 선점 순으로 우선 |

앱 첫 화면의 **📖 오목 기술·공식 → [기술·공식 보기]** 에서 용어와 원리를 볼 수 있습니다.

**VCT 검증** : 무작위로 만든 중반 판 약 500개에서 VCT가 "필승"이라고 한 경우를 실제로 끝까지 두어 보았습니다. (수비는 깊이 탐색 AI가 최선으로 막음)

| 규칙 | VCT가 필승이라고 한 판 | 실제로 이긴 판 |
|---|---|---|
| 자유룰 | 14 | 14 |
| 렌주룰 | 3 | 3 |

(처음 검증에서는 10판 중 8판이었는데, 실패 원인 — 다음 수에서 탐색 시간이 모자라 수순을 놓침 — 을 찾아 "필승 계획 기억"과 "짧은 수순부터 탐색"을 넣어 고쳤습니다.)

> 26주형의 이름·번호와 일부 위치(D1 한성 h10, I1 장성 j10)·평가는 공개 자료로 확인했고, 나머지 흑 3수 위치는 표준 주형 배치도를 따랐습니다. 대회용으로 쓸 때는 렌주 교재와 한 번 더 대조해 보세요.

### 3-2. 패배 학습 (복기) — `GameTracker.java`, `GameReview.java`, `LearnedBook.java`

질 때마다 그 판을 복기해서 더 나은 수를 기억하고, 다음에 같은 판이 나오면 그 수를 1순위로 추천합니다.

1. **기보 기록** (`GameTracker`) : 화면에서 읽은 판을 이전 판과 비교해 새로 생긴 돌을 그 사이의 수로 기록합니다. 두 수가 한꺼번에 보이면 차례로 순서를 정하고, 돌이 줄어들면 새 판으로 봅니다. 5목이 생기면 판이 끝납니다.
2. **복기** (`GameReview`) : 진 쪽이 둔 수를 마지막부터 최대 20수 거슬러 보면서, *"이 수를 둔 뒤 상대에게 필승(5목 자리·VCF·VCT·깊이 탐색 필승)이 생겼는데, 다른 수였다면 없었던"* 자리를 찾습니다. 가장 마지막의 결정적 실수 하나를 배웁니다.
3. **배운 수 기억** (`LearnedBook`) : "이 판 + 둘 차례 + 규칙 → 이 수"를 저장합니다. 판을 돌리거나 뒤집은 8가지 모양을 같은 판으로 봅니다. 최대 500개, 기기 안에만 저장됩니다.
4. **추천에 사용** : 배운 판이 나오면 그 수를 1순위로 올리고 `📚 지난 패배에서 배운 수`라고 표시합니다. 단, 바로 이기는 수·5목 막기·필승 수순이 있으면 그것이 먼저입니다.

- 추천 받을 돌을 흑/백으로 정해 두면 **내가 진 판**에서, '자동'이면 **진 쪽의 실수**에서 배웁니다.
- 첫 화면 **📚 패배 학습**에서 켜고 끌 수 있고, 통계 확인, 배운 내용 초기화, **최근 기보 복사**(최대 10판)를 할 수 있습니다. 복사한 기보를 보내 주면 그 판들을 보고 엔진 자체를 개선할 수 있습니다.

**한계** : 상대의 필승을 증명할 수 있는 *전술적인* 실수만 찾습니다. 천천히 불리해지는 형세 판단 실수는 찾지 못할 수 있습니다 (실제 대국 5판 복기 시험에서 2판은 실수를 찾았고, 3판은 "찾지 못함"으로 끝남). 또 똑같은 판이 다시 나와야 쓰이므로, 매번 다르게 두는 상대보다 같은 수순을 반복하는 상대(게임 속 AI 등)에게 효과가 큽니다.

### 3-3. 깊이 탐색 AI — `DeepSearch.java`
답이 바로 정해지지 않는 판에서는 여러 수 앞을 읽어서 순위를 정합니다.

| 기법 | 설명 |
|---|---|
| 알파-베타 탐색 (negamax) | "내가 두면 → 상대는 최선으로 받고 → 나는 또 …"를 여러 수 앞까지 계산. 볼 필요가 없는 가지는 잘라 냄 |
| 반복 심화 | 1수, 2수, 3수 … 순서로 깊이를 늘리다 제한 시간(0.5/1.5/3초)이 되면 마지막 완성 결과 사용 |
| 치환표 + Zobrist 해시 | 이미 계산한 판을 64비트 번호로 기억해서 다시 계산하지 않음 |
| 위협 확장 | 상대가 4를 만들어 반드시 막아야 하는 수는 깊이를 줄이지 않고 끝까지 따라감 |
| 후보 줄이기 | 점수가 높은 상위 8~12개 수만 검토. 상대에게 큰 위협이 있으면 막는 수와 내 4만 검토 |
| 패턴 표 캐싱 | 한 줄(3¹⁰ = 59,049가지)의 모양 판정 결과를 표에 저장해 탐색 속도를 높임 |

결과로 추천 수, 예상 수순(예: `H8 → I9 → G7 …`), 탐색한 깊이가 패널에 표시됩니다.

**실력 개선 (자가 대국으로 측정)** — 개선 전 버전을 따로 저장해 두고, 같은 시작 배치에서 흑백을 바꿔 가며 100판씩 대국

| 개선 기법 | 내용 |
|---|---|
| 날카로운 형세 판단 | 탐색 끝 판에서 둘 차례인 쪽이 열린 4·4-4·금수 유도 4를 만들 수 있으면 사실상 승리, 4-3 준비면 크게 유리로 판단 |
| 킬러 수 · 히스토리 | 다른 가지에서 가지치기를 일으킨 수를 먼저 검토 |
| PVS | 가장 유력한 수만 정확히, 나머지는 "더 나은지"만 좁은 창으로 빠르게 확인. 루트는 상위 3개만 정확한 점수 |

| 조건 (수당 0.2초) | 개선 버전 : 개선 전 | 점수율 |
|---|---|---|
| 세 기법 모두, 자유룰 | 64 : 35 (무 1) | 64.5% (약 +100 Elo) |
| 세 기법 모두, 렌주룰 | 64 : 36 | 64.0% (약 +100 Elo) |
| 날카로운 판단 빼고 | 58 : 42 | 58.0% |
| 킬러·히스토리 빼고 | 61 : 38 (무 1) | 61.5% |
| PVS 빼고 | 54 : 46 | 54.0% |

→ 어느 하나를 빼도 점수가 내려가므로 세 기법 모두 사용합니다. (100판 기준 오차 약 ±10%)

**점수 가중치 자가 대국 조정** — 값 하나만 바꾼 버전과 지금 버전을 200판씩 대국 (수당 0.06초, 오차 약 ±7%)

| 바꾼 값 | 점수율 | 결과 |
|---|---|---|
| 4 점수 1500 → 3000 | 53.0% (400판 재확인 52.4%) | 차이 없음 → 유지 |
| 열린 3 점수 1000 → 2000 / 700 | 42.3% / 50.5% | 올리면 약해짐 → 유지 |
| 닫힌 3 150 → 400, 열린 2 100 → 300 | 50.2% / 49.5% | 차이 없음 → 유지 |
| 수비 비율 80% → 100% / 60% | 48.3% / 48.0% | 차이 없음 → 유지 |
| 형세 판단의 상대 모양 비율 90% → 110% | 42.0% | 약해짐 |
| **형세 판단의 상대 모양 비율 90% → 70%** | **59.8%** (0.2초 자유룰 54.5%, 렌주룰 51.0%, 합계 400판 56.2%) | **채택** |
| 형세 판단의 상대 모양 비율 90% → 50% | 58.0% | 70%와 비슷 → 70% 사용 |

**최종 결과 (개선 전 버전과 100판씩, 수당 0.2초)**

|---|---|---|
| 자유룰 | 66 : 34 | 66.0% (약 +115 Elo) |
| 렌주룰 | 61 : 39 | 61.0% (약 +78 Elo) |

### 4. 오버레이 표시 — `OverlayController.java`, `OverlayShapes.java`

**오버레이가 인식을 방해하지 않게 하는 방법**
- 화면 캡처에는 이 앱이 그린 추천 고리·배지·인식 점도 함께 찍힙니다. 그래서 그린 위치를 `OverlayShapes`로 정확히 계산해 인식기에 넘기고, 인식기는 그 픽셀을 **건너뛰고** 게임 화면 픽셀만 봅니다. (예전에는 '작게' 크기에서 추천 고리 위에 둔 돌을 못 읽어 판이 멈추는 문제가 있었고, 이 방법으로 고쳤습니다)
- 패널이 바둑판을 가리면 바둑판 위나 아래 빈 곳으로 자동으로 옮기고, 옮길 곳이 없으면 패널에 경고를 띄웁니다.
- 판 맞추기 화면이 떠 있는 동안은 인식하지 않습니다.
- 흑·백 돌 개수가 맞지 않으면(흑 = 백 또는 백 + 1이 아니면) 인식 오류일 수 있다고 경고합니다.
- 안드로이드 14 이상에서 화면 녹화 허용 창에 '앱 하나'가 있으면 게임만 골라 녹화할 수 있고, 이때는 이 앱의 표시가 아예 찍히지 않습니다.

`TYPE_APPLICATION_OVERLAY` 창을 게임 위에 띄웁니다. 표시 창은 터치를 통과시키므로 게임 조작에 방해가 되지 않습니다.
표시 고리도 화면 캡처에 함께 찍히기 때문에, 돌 인식에 쓰는 교차점 한가운데는 비워 두고 바깥쪽 고리만 그립니다.
