# 오목 도우미 (Omok Helper)

스마트폰 화면에 보이는 오목 바둑판을 **실시간으로 감지**해서, 다음에 둘 좋은 자리를 게임 화면 위에 표시해 주는 안드로이드 앱입니다.
정보 수행평가(모의 테스트)용으로 만든 프로젝트입니다.

## 설치 방법

1. 이 저장소의 **Releases → `latest`** 에서 `OmokHelper.apk` 를 휴대폰으로 다운로드합니다.
   (또는 **Actions** 탭 → 가장 최근 빌드 → `OmokHelper-apk` 다운로드 후 압축 해제)
2. 휴대폰에서 APK를 열어 설치합니다. "출처를 알 수 없는 앱" 설치 허용이 필요할 수 있습니다.

## 사용 방법

1. 앱에서 **판 크기(15/19)** 와 **규칙(자유룰/렌주룰)** 을 게임과 같게 고르고, **AI 생각 시간**(0.5/1.5/3초)을 정합니다.
2. **다른 앱 위에 표시** 권한을 허용합니다.
3. **화면 감지 시작** → 화면 녹화를 허용합니다.
4. 오목 게임을 열고, 떠 있는 패널의 **[판 맞추기]** 를 누릅니다.
5. 바둑판의 **맨 왼쪽 위 교차점**, **맨 오른쪽 아래 교차점** 을 차례로 맞추고 **[저장]** 합니다.
6. 이제 판이 바뀔 때마다 추천 자리에 고리가 나타납니다. (빨강 1순위 · 주황 2순위 · 파랑 3순위 이하)
   패널에는 좌표와 이유(예: `H8 4-3 공격 (필승)`), 필승 수순이 표시됩니다.

### 패널의 [설정]

| 항목 | 설명 |
|---|---|
| 판 프리셋 | `[저장 1~3]` : 지금 바둑판 위치와 크기(15/19줄)를 저장 · `[1~3]` : 저장한 위치를 바로 불러오기. 게임이나 화면 배치마다 저장해 두면 [판 맞추기]를 다시 할 필요가 없습니다 |
| 표시 크기 | 작게 / 보통 / 크게 — 추천 고리와 패널 글자 크기 |
| 추천 색 | 기본 · 네온 · 파스텔 · 고대비 · 흑백 (누를 때마다 다음 색) |
| 패널 색 | 다크 · 라이트 · 네이비 · 우드 · 반투명 (누를 때마다 다음 색) |

표시 크기를 바꿔도 추천 고리는 돌 인식에 쓰는 교차점 한가운데를 가리지 않도록 설계했고, 모든 색·크기 조합에서 고리가 돌로 잘못 인식되지 않는지 테스트로 확인합니다.

## 동작 원리

```
화면 캡처 ──▶ 바둑판 인식 ──▶ 수 분석 ──▶ 오버레이 표시
(0.6초마다)   (색상 판별)     (패턴+탐색)   (추천 고리)
```

### 1. 화면 캡처 — `CaptureService.java`
안드로이드의 `MediaProjection` API로 화면을 0.6초마다 이미지로 받아 옵니다.
같은 판이 두 번 연속 읽혀야 확정해서, 돌이 놓이는 애니메이션 중간 화면은 무시합니다.

### 2. 바둑판 인식 — `BoardDetector.java`
- 사용자가 맞춘 두 모서리 좌표로 15×15(또는 19×19)개 교차점의 위치를 계산합니다.
- 각 교차점 주변 작은 원 안 픽셀들의 **밝기·채도 중앙값**을 구합니다. (중앙값을 쓰면 선이나 마지막 수 표시에 덜 흔들립니다)
- 칸 한가운데에서 잰 **바둑판 색**과 비교해서
  - 훨씬 어두우면 → 흑돌
  - 밝고 무채색이면 → 백돌
  - 그 외 → 빈칸

### 3. 수 분석 — `OmokEngine.java`
| 단계 | 내용 |
|---|---|
| 패턴 분석 | 빈칸에 돌을 놓았다고 가정하고 4방향(가로·세로·두 대각선)의 모양을 판별: 5목, 열린4, 4, 열린3, 3, 열린2, 2 |
| 점수 계산 | **공격 점수**(내가 둘 때) + **수비 점수**(상대가 둘 때 × 0.8). 4-4, 4-3, 3-3 같은 복합 공격은 큰 점수 |
| VCF 탐색 | 4를 연속으로 두어 이기는 수순(Victory by Continuous Fours)을 깊이 우선 탐색. 있으면 최우선 추천 |
| 상대 VCF 차단 | 상대에게 필승 수순이 있으면 그 자리에 가산점 |
| 한 수 앞 보기 | 상위 후보에 대해 "내가 둔 뒤 상대의 최선 공격"을 계산해 위험한 수를 감점 |
| 렌주룰 | 흑의 3-3, 4-4, 장목(6목 이상)을 금수로 판정해 추천에서 제외 |

### 3-1. 깊이 탐색 AI — `DeepSearch.java`
답이 바로 정해지지 않는 판에서는 여러 수 앞을 읽어서 순위를 정합니다.

| 기법 | 설명 |
|---|---|
| 알파-베타 탐색 (negamax) | "내가 두면 → 상대는 최선으로 받고 → 나는 또 …"를 여러 수 앞까지 계산. 볼 필요가 없는 가지는 잘라 냄 |
| 반복 심화 | 1수, 2수, 3수 … 순서로 깊이를 늘리다 제한 시간(0.5/1.5/3초)이 되면 마지막 완성 결과 사용 |
| 치환표 + Zobrist 해시 | 이미 계산한 판을 64비트 번호로 기억해서 다시 계산하지 않음 |
| 위협 확장 | 상대가 4를 만들어 반드시 막아야 하는 수는 깊이를 줄이지 않고 끝까지 따라감 |
| 후보 줄이기 | 점수가 높은 상위 8~12개 수만 검토. 상대에게 큰 위협이 있으면 막는 수와 내 4만 검토 |
| 패턴 표 캐싱 | 한 줄(3¹⁰ = 59,049가지)의 모양 판정 결과를 표에 저장해 탐색 속도를 높임 |

결과로 추천 수, 예상 수순(예: `H8 → I9 → G7 …`), 탐색한 깊이가 패널에 표시됩니다.

**성능 비교 (같은 PC에서 12판 대국, 흑백 번갈아)**

| 깊이 탐색 생각 시간 | 깊이 탐색 AI | 기존 빠른 분석 AI | 무승부 |
|---|---|---|---|
| 0.3초 | 9승 | 2승 | 1 |
| 1초 | 11승 | 1승 | 0 |

### 4. 오버레이 표시 — `OverlayController.java`
`TYPE_APPLICATION_OVERLAY` 창을 게임 위에 띄웁니다. 표시 창은 터치를 통과시키므로 게임 조작에 방해가 되지 않습니다.
표시 고리도 화면 캡처에 함께 찍히기 때문에, 돌 인식에 쓰는 교차점 한가운데는 비워 두고 바깥쪽 고리만 그립니다.

## 프로젝트 구조

```
app/src/main/java/com/omokhelper/
├── MainActivity.java       첫 화면 (설정, 시작/중지)
├── CaptureService.java     화면 캡처 → 인식 → 분석 → 표시 반복
├── BoardDetector.java      이미지에서 돌 읽기
├── OmokEngine.java         추천 엔진 (패턴, 점수, VCF, 렌주 금수)
├── DeepSearch.java         깊이 탐색 AI (알파-베타, 반복 심화, 치환표)
├── OverlayController.java  게임 위 표시 창, 조작 패널(설정·프리셋), 판 맞추기 화면
├── Themes.java             추천 색 / 패널 색 테마
└── Prefs.java              설정 + 판 프리셋 저장
app/src/test/java/com/omokhelper/
├── OmokEngineTest.java     엔진 테스트 (5목, 막기, 4-3, VCF, 금수 등)
├── BoardDetectorTest.java  가짜 게임 화면으로 인식 테스트
└── DeepSearchTest.java     깊이 탐색 테스트
```

## 직접 빌드하기

Android SDK가 설치된 PC에서:

```bash
./gradlew testDebugUnitTest   # 테스트
./gradlew assembleRelease     # APK → app/build/outputs/apk/release/
```

GitHub에 push 하면 GitHub Actions가 자동으로 테스트하고 APK를 만들어 `latest` 릴리스에 올립니다.

## 한계

- 세로 화면 기준입니다. 화면을 돌리거나 바둑판 위치가 바뀌면 [판 맞추기]를 다시 해야 합니다.
- 바둑판과 돌 색이 비슷한 특이한 테마에서는 인식이 틀릴 수 있습니다.
- 돌 개수로 차례를 추정합니다(흑이 먼저). 접바둑처럼 개수가 맞지 않으면 차례가 틀릴 수 있습니다.

## 사용 시 주의

연습, AI 대전, 모의 테스트용으로 만들었습니다. 사람과 하는 온라인 대국에서 사용하면 상대에게 불공정하고, 게임 이용약관 위반으로 계정이 제재될 수 있습니다.
